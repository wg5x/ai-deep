# 选择优先原则

> 日期：2026-06-07
> 状态：生效
> 适用范围：AI 商业实验室 / 机会选择 / 通道选择 / 开发决策

## 1. 核心判断

```text
选择要比努力重要。
```

AI 很容易进入“努力执行”状态，但本项目首先要判断：

```text
这件事值不值得做？
这是不是当前最该做的事？
有没有更省力、更借力、更接近现金流的路？
```

如果选择错了，执行越强，浪费越大。

## 2. 选择优先于开发

当出现一个工具、通道、自动化或产品想法时，默认顺序是：

```text
先判断方向
→ 再找借力方案
→ 再做人工验证
→ 最后才开发
```

不要把“我能做”误判成“我应该做”。

## 3. 选择标准

一个方向进入执行前，必须先问：

- 它是否直接服务现金流验证？
- 它是否比其他方向更接近真实客户、真实反馈或真实收入？
- 它是否能借现成平台、开源项目、第三方工具或人工流程完成？
- 它是否能在 1-7 天内给出明确反馈？
- 它失败后是否容易复盘和掉头？
- 它是否会制造长期维护成本？
- 它是否只是因为 AI 做得出来，所以才被推进？

## 4. 努力的正确位置

努力不是不重要。

但努力应该放在：

- 选定的高价值方向
- 已经出现真实需求的机会
- 能低成本验证的实验
- 能复用为模板的流程
- 能沉淀项目内核的判断

不要把努力浪费在：

- 没有买家证据的系统建设
- 还没验证需求的自动化
- 为了显得完整而做的功能
- 可由现成工具解决的自研接入
- 用户没有要求、现金流也不需要的基础设施

## 5. Agent 执行约束

Agent 在动手前必须先做选择判断。

当用户给出一个方向时，Agent 不应默认进入开发，而应先判断：

```text
做不做？
现在做不做？
自己做还是借力？
能不能先人工验证？
做错了能不能低成本退回？
```

如果答案不清楚，应先给出判断，而不是用执行掩盖选择问题。

## 6. 一票否决

出现以下情况，默认暂停或降级为调研：

- 方向不能解释如何接近现金流
- 执行成本明显高于验证价值
- 现成工具足够用却选择自研
- 需要用户持续高投入才能推进
- 一旦失败会留下高维护成本
- 只是为了把系统做完整，而不是为了验证商业价值

## 7. 项目口径

```text
先选对战场，再努力打仗。
先找船，再划桨。
先验证值不值，再证明能不能。
```
