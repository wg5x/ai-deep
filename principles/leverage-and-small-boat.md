# 借力与小船原则

> 日期：2026-06-07  
> 状态：生效  
> 适用范围：AI 商业实验室 / 机会判断 / 实验设计

## 1. 核心判断

我们是小公司、小项目定位。

在没有做大之前，不能重资产、不能过早复杂化、不能靠蛮力硬做。

必须依靠：

```text
借力
小步
可落地
可试错
小船好掉头
```

## 2. 借力

借力不是偷懒，而是商业智慧。

优先借：

- 开源项目
- 现有平台
- 已有用户注意力
- 用户的人脉和本地资源
- 公开政策和行业资料
- 小红书/B站/微信等成熟渠道
- 第三方工具和自动化服务
- AI 生成、整理、分析和交付能力

但真实关系资源不是免费资源。

启用用户身边的人脉、本地朋友或熟人商家前，必须先判断：

```text
用户是否愿意启用？
关系压力是否低？
失败是否不伤关系？
不用这个资源是否也能继续推进？
这个资源能否复制，还是只能用一次？
```

如果用户不舒服，立即转向公开市场或其他低社会成本路径。

默认不要先自研：

- 爬虫平台
- CRM
- 复杂后台
- 支付系统
- 官网
- App
- 大模型运行时
- 大型数据库

除非已经证明：

```text
有人愿意付钱，并且现有工具确实卡住了增长。
```

## 3. 小船

小船原则：

```text
小投入
小样例
小范围
小价格
小周期
小风险
快反馈
快复盘
快转向
```

一个机会如果无法在 1-7 天内形成某种低风险验证，应先降级为调研，不进入执行优先级。

## 4. 判断问题

每个机会必须问：

```text
能不能借现成平台？
能不能借开源工具？
能不能借用户已有资源？
用户是否愿意启用这个资源？
这个资源失败后是否不伤关系？
能不能用人工+AI 先服务化验证？
能不能不写代码先收反馈？
能不能 7 天内知道对错？
失败成本是否足够低？
掉头是否容易？
```

## 5. 反面信号

出现以下情况要警惕：

- 一上来就想做平台
- 一上来就要注册公司/买域名/开发 App
- 没有客户就开始搭后台
- 没有付费就设计复杂自动化
- 为了显得高级而增加流程
- 每次失败都很贵、很慢、很难复盘

## 6. 项目口径

```text
借别人的船过河。
用自己的判断赚钱。
在小水域里练会，再去大海。
```

## 7. 成功标准

一个实验符合本原则，必须满足：

- 可用现有工具完成 80%
- 最小交付清楚
- 外部动作可控
- 失败成本低
- 关系成本低
- 复盘结果明确
- 有机会沉淀成模板
