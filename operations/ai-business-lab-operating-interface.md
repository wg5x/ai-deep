# AI 商业实验室操作界面方案

> 日期：2026-06-07  
> 状态：v0.1 方案  
> 目的：把“主动发散、商业筛选、AI 落地、复盘升级”变成可执行工作台

## 1. 核心定位

AI 商业实验室不是新闻工具，也不是单纯调研工具。

它是一个持续运行的商业操作台：

```text
输入现实信号
→ 扩展机会面
→ 筛选商业实验
→ 打包现金流服务
→ 收集真实反馈
→ 升级项目内核
```

## 2. 操作界面模块

### 2.1 Signal Inbox

输入：

- 时政新闻
- 高考/世界杯/节假日
- 平台热点
- 政策法规
- GitHub 开源项目
- 北京本地场景
- 用户随口提到的直觉

输出：

```text
可进入扩展的种子信号
```

### 2.2 Expansion Board

使用 `strong-brainstorming` 和 `opportunity-expansion-engine`。

把一个点扩展成：

```text
远近联想
相邻/相反/隐喻/情绪/文化符号
10 个机会面
100 个素材/问题/案例/渠道/人群
```

输出：

```text
机会森林，而不是单点想法
```

强脑暴层负责让想象力足够远，机会扩展层负责把想象力收回到商业实验。

### 2.3 Opportunity Portfolio

把机会分成三类：

| 类型 | 目标 |
|---|---|
| 小实验 | 7 天内验证现金流 |
| 中实验 | 验证可复制服务 |
| 大实验 | 孵化长期事业 |

默认资源分配：

```text
70% 小实验
20% 中实验
10% 大实验
```

### 2.4 Offer Factory

使用 `cashflow-offer-builder`。

把机会打包成：

- 服务名
- 目标买家
- 第一价格
- 交付物
- 触达话术
- 样例页
- 风险边界

### 2.5 Experiment Queue

使用 `venture-experiment-designer`。

每个实验必须有：

```text
7 天动作
成功标准
失败标准
反馈记录
继续/转向/停止决策
```

### 2.6 Feedback Ledger

使用 `business-retrospective`。

记录：

- 回复
- 私信
- 通话
- 试用
- 付款
- 拒绝原因
- 复购
- 转介绍

### 2.7 Kernel Upgrade

将真实反馈写回：

- skills
- methods
- rubrics
- reports
- run logs
- changelog

## 3. 商业落地路径

第一阶段不做大平台。

先做：

```text
AI 增强型服务工作室
```

用服务验证现金流，再把重复交付产品化。

路径：

```text
内容吸引
→ 私域/线下反馈
→ 低价样例包
→ 定制服务
→ 月度陪跑
→ 自动化工具
→ 服务端商业实验系统
```

## 4. 界面不是装饰

未来如果做成产品界面，第一屏不应是宣传页，而应是工作台：

```text
今日信号
扩展中的机会面
本周实验
待打包报价
真实反馈
现金流记录
内核升级
```

## 5. 成功标准

```text
不是生成了多少想法。
不是写了多少报告。
而是 AI 是否持续帮助用户发现、验证并放大可赚钱机会。
```

可量化指标：

- 每周有效信号数
- 每周机会扩展数
- 每周实验数
- 回复数
- 付费数
- 复购/转介绍数
- 每次失败沉淀的规则数

## 6. 下一步

把高考生命周期调研作为第一个 `1 → 10 → 100` 样例，继续扩展：

```text
高考 → 志愿填报/本地消费/教育服务/内容产品/机构效率工具
```
