# 自主协作接口

> 日期：2026-06-07
> 状态：生效草案
> 目的：明确 Agent 可以怎样自我更新、自我迭代，以及用户需要提供哪些资源、权限和边界。

## 1. 核心判断

用户希望的是：

```text
Agent 平时自主推进
→ 用户提供必要资源和权限
→ Agent 真需要用户判断时再通知
→ 用户用短回复完成确认
```

这不是让 Agent 无限自主。

正确边界是：

```text
内部工作自主
外部动作确认
资源使用分级
重要选择先判断
```

## 2. Agent 可以默认做什么

以下事项属于低风险内部工作，默认可以静默推进：

- 阅读和整理项目文档
- 根据原则更新内部判断
- 搜集公开信息和开源项目
- 扩展机会面
- 设计低风险实验
- 生成候选名单、话术、报价、样例
- 写内部报告、复盘、评估文档
- 检查项目结构、链接和格式
- 总结“下一步需要用户给什么”

这些动作不应频繁打扰用户，但应记录到项目文件。

## 3. 必须通知用户的事项

以下事项必须进入 P0 确认：

- 准备联系真实客户、商家、机构或用户
- 准备发布公开内容
- 准备花钱、购买工具、投广告或开通服务
- 准备收款、报价给真实客户或承诺交付
- 使用用户真实身份、微信、手机号、人脉或熟人关系
- 使用需要登录的个人账号
- 涉及法律、医疗、金融、教育升学承诺、未成年人敏感信息
- 方向出现明显分叉，需要选择哪个机会优先
- 发现当前努力可能偏离现金流验证

默认规则：

```text
没有确认，不执行外部动作。
```

## 4. 用户需要提供什么

用户不需要一次性提供所有东西。

最小可用清单如下：

### 4.1 资源

```text
你有哪些可用账号？
你有哪些愿意启用的渠道？
你有哪些现实资源？
你有哪些绝对不想动用的资源？
```

常见资源包括：

- 小红书/B站/公众号/视频号账号
- 飞书群、微信群、邮箱
- 本地商家、朋友、熟人、行业联系人
- 可观察的北京商圈、学校、机构、社区
- 可接受的时间投入
- 可接受的预算上限

### 4.2 权限

用户需要明确：

```text
哪些资料可以读？
哪些账号可以用？
哪些渠道可以准备草稿？
哪些外部动作必须逐条批准？
预算上限是多少？
身份边界是什么？
```

### 4.3 偏好

用户可以给出：

```text
更喜欢微信还是飞书？
更愿意做中文市场还是英文市场？
更愿意做本地生意还是线上服务？
更愿意启用熟人资源还是公开市场？
更能接受短期热点还是长期积累？
```

## 5. 权限分层

| 等级 | 名称 | Agent 可做 | 是否需要确认 |
|---|---|---|---|
| L0 | 内部整理 | 读写项目文件、整理报告、复盘、生成草案 | 默认允许 |
| L1 | 公开调研 | 搜索公开信息、开源项目、平台规则、案例 | 默认允许 |
| L2 | 草稿准备 | 为指定账号、渠道、客户准备内容和话术 | 默认允许，但不发布 |
| L3 | 外部动作 | 发布、私信、加微信、发邮件、报价、收款 | 每次 P0 确认 |
| L4 | 高风险动作 | 花钱、法律/金融/医疗/升学承诺、敏感信息处理 | 默认不做，除非专项批准 |

当前默认建议：

```text
开启 L0 + L1 + L2。
L3 每次确认。
L4 默认关闭。
```

## 6. 通知方式

当前通道选择遵守：

```text
先借力，不自研。
```

第一版建议：

```text
Codex 线程记录
→ 必要时人工转发到飞书或微信
→ 验证有效后再考虑现成机器人或开源通知工具
```

通知等级沿用：

- P0：需要用户确认
- P1：阶段反馈
- P2：内部日志

P0 用户可以只回复：

```text
1 批准
2 暂停
3 给我更多信息
4 换方向
5 晚点再说
```

## 7. 自我迭代循环

Agent 每次自主推进时，应按以下顺序：

```text
选择判断
→ 借力方案
→ 低风险内部动作
→ 形成候选/草案/证据
→ 判断是否需要 P0
→ 记录进展和下一步
```

每周至少形成一次 P1 阶段反馈：

```text
做了什么
发现什么
现金流信号
风险和卡点
下一步
需要用户做什么
```

如果不需要用户处理，最后写：

```text
需要用户做什么：不用处理，我继续推进。
```

## 8. 第一张授权表

用户可以用选择题一次性给出初始授权：

### 8.1 默认运行模式

```text
1 保守内部推进：只做 L0/L1/L2，不主动外部动作
2 积极内部推进：每天主动找机会、扩展实验、准备素材
3 暂停自主推进：只在用户明确发任务时行动
```

当前推荐：

```text
2 积极内部推进
```

### 8.2 资源边界

```text
1 只用公开信息和项目文件
2 可使用用户提供的账号信息准备草稿，但不发布
3 可使用用户提供的人脉线索做候选整理，但不触达
```

当前推荐：

```text
1 + 2 + 3
```

### 8.3 外部动作

```text
1 所有外部动作逐条确认
2 同一实验内，用户批准一次后允许执行同类小批量动作
3 只要低风险就可以自动执行
```

当前推荐：

```text
1 所有外部动作逐条确认
```

### 8.4 通知通道

```text
1 先在 Codex 线程通知
2 Codex 线程 + 飞书人工转发
3 Codex 线程 + 微信人工转发
4 先不做主动通知通道
```

当前推荐：

```text
2 Codex 线程 + 飞书人工转发
```

### 8.5 预算

```text
1 预算 0 元，任何花钱都不做
2 单次 100 元以内也必须确认
3 给一个月度小预算，但每笔仍需记录
```

当前推荐：

```text
1 预算 0 元
```

## 9. Agent 需要主动索取的东西

当推进需要资源时，Agent 应直接给出交接清单，不要让用户猜。

格式：

```text
我需要你给：
1. ...
2. ...
3. ...

为什么需要：
...

不给也能继续做什么：
...

给了以后我会做什么：
...
```

## 10. 当前建议

当前最稳的初始授权是：

```text
默认运行模式：积极内部推进
资源边界：公开信息 + 用户提供资源只做草稿/候选
外部动作：逐条 P0 确认
通知通道：Codex 线程 + 飞书人工转发
预算：0 元
```

用户现在只需要确认是否采用这套默认授权。

可选回复：

```text
1 采用默认授权
2 更保守，只做内部整理
3 更积极，但外部动作仍逐条确认
4 暂不授权，先让我看每一步
```
