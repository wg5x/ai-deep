## 1. Google: Agentic Gemini Era

Source:

- https://blog.google/innovation-and-ai/technology/developers-tools/google-io-2026-collection/
- https://blog.google/innovation-and-ai/products/gemini-app/next-evolution-gemini-app/

Evidence used:

- Google I/O 2026 collection frames the direction as moving from AI tools that help write to agents that help act.
- Google announced Gemini Spark as a 24/7 personal AI agent and Daily Brief as a proactive personalized brief.
- Google describes Spark as working in the background across connected apps and asking first before high-stakes actions.

Supported claims:

- Always-on personal agents are becoming a product category.
- Agent products increasingly need connected context, recurring tasks, and human approval for risky actions.

Limitations:

- Product claims are from Google official announcements and may emphasize strategic positioning.

## 2. Microsoft: Build 2026 Agent Platform And Scout

Source:

- https://blogs.microsoft.com/blog/2026/06/02/microsoft-build-2026-be-yourself-at-work/

Evidence used:

- Microsoft announced Microsoft IQ as a context layer for agents across enterprise and world knowledge.
- Microsoft announced Scout as an always-on personal agent for work.
- Microsoft emphasized governance, security, observability, local/cloud sandboxes, agent control, and choice across models and tools.

Supported claims:

- Context, governance, and control are becoming core agent infrastructure.
- Always-on agents are moving into work contexts.

Limitations:

- Enterprise-focused framing may not directly translate to small-team buying behavior.

## 3. OpenAI: Agents SDK

Source:

- https://openai.github.io/openai-agents-python/
- https://openai.github.io/openai-agents-python/tracing/
- https://openai.github.io/openai-agents-python/mcp/

Evidence used:

- The Agents SDK uses a compact set of primitives: agents, tools, handoffs, guardrails, tracing, sessions, MCP, and human-in-the-loop controls.
- Built-in tracing records agent runs, tool calls, handoffs, guardrails, and custom events.

Supported claims:

- Agent runtime implementation is becoming more standardized.
- Durable product value should move toward mission, judgment, memory, workflow, and distribution rather than runtime implementation alone.

Limitations:

- Developer framework adoption does not automatically prove customer demand for a specific commercial product.

## 4. Anthropic: Multi-Agent Research System

Source:

- https://www.anthropic.com/engineering/multi-agent-research-system

Evidence used:

- Anthropic describes an orchestrator-worker pattern for multi-agent research.
- Anthropic reports strong internal results for breadth-first research tasks.
- Anthropic notes that multi-agent systems consume far more tokens than ordinary chat and are most appropriate when task value justifies the cost.

Supported claims:

- Deep research should be selectively triggered for high-value signals.
- Lightweight scanning plus selective escalation is a better default operating model than deep research on every signal.

Limitations:

- Anthropic's reported results are internal evaluations and may not generalize to all research tasks or runtimes.
