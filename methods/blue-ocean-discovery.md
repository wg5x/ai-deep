# 商业蓝海发现方法

> 日期：2026-06-07  
> 状态：生效草案  
> 适用范围：AI机会雷达 / 中国本土 AI 商业机会发现

## 1. 蓝海定义

本项目中的“蓝海”不是指没人做。

更准确的定义是：

```text
需求正在变强，
供给还不成熟，
用户愿意尝试，
小团队能低成本验证，
且政策/平台环境允许探索的商业机会。
```

## 2. 蓝海来源

蓝海信号来自 7 类输入：

1. 政策鼓励方向
2. 监管变化带来的新合规需求
3. 大厂新能力下沉后形成的新服务空间
4. 中国平台用户反复表达的痛点
5. 企业数字化/降本增效中的低效流程
6. 北京本地产业和场景开放
7. 海外产品在中国本土尚未被充分改造的模式

## 3. 蓝海判断框架

每个候选机会都要问：

```text
谁痛？
为什么现在更痛？
现在怎么解决？
现有方案哪里不好？
谁会付钱？
能不能小成本验证？
政策/平台是否允许？
我们是否能比大厂更快切入？
```

## 4. 优先找的蓝海

第一阶段优先找：

- 服务化先行、产品化后置的机会
- 可以用内容获客的机会
- 可以通过微信/线下建立信任的机会
- 可以用定制报告/咨询/小工具试单的机会
- AI 能显著降低交付成本的机会
- 北京本地能找到真实反馈对象的机会

暂时不优先找：

- 需要大量资本投入的机会
- 需要复杂牌照的机会
- 需要大规模企业销售的机会
- 需要强平台资源的机会
- 容易踩监管红线的机会

## 5. 蓝海候选输出格式

每个蓝海候选必须写成：

```text
机会名称：
一句话描述：
用户是谁：
痛点是什么：
为什么现在：
现有替代方案：
政策/平台信号：
最小产品/服务：
第一付费形态：
第一验证渠道：
风险：
7天验证动作：
继续/放弃标准：
```

## 6. 蓝海与伪蓝海

警惕伪蓝海：

- 只是技术很新，但没人付钱
- 只是政策提到，但没有真实需求
- 只是竞争少，但市场也小
- 只是内容热，但转化弱
- 只是自己感兴趣，但用户不痛
- 只是大厂没做，但大厂一做就封死

真正的蓝海要能进入验证：

```text
有人愿意聊
有人愿意试
有人愿意给具体场景
有人愿意付小钱
```
