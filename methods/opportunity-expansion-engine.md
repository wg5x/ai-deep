# 机会扩展引擎方法

> 日期：2026-06-07  
> 状态：生效草案  
> 适用范围：AI 商业实验室 / 点到面扩展 / 商业落地方案

## 1. 核心目标

用户给一个点，系统不能只完成这个点。

系统必须默认执行：

```text
1 → 10 → 100 → 3 → 1
```

含义：

- `1`：一个信号、想法、事件、直觉
- `10`：十个机会面
- `100`：素材、问题、案例、用户、渠道、产品形态
- `3`：筛出三个最值得实验的方向
- `1`：先落一个现金流实验

在进入商业扩展前，如果用户给的是抽象词、隐喻、情绪、审美方向，或用户明确要求更大的发散力度，应先执行强脑暴：

```text
字面 → 相邻 → 相反 → 隐喻 → 情绪 → 尺度跃迁 → 文化符号 → 商业角度
```

例如：

```text
蓝色
→ 天空、海洋、绿色、红色、寒冷、自由、忧郁、宇宙、星球、科技屏幕、品牌信任
→ 旅游、音乐、冥想、运动、饮料、服装、空间设计、数字产品、仪式活动
```

## 2. 输入

```text
高考
世界杯
AI 智能体
北京文旅
某个开源项目
某个政策
某个小红书现象
用户随口提到的一个生意想法
```

## 3. 十个机会面

| 面 | 要问的问题 |
|---|---|
| 时间面 | 之前、当中、之后、长期会发生什么？ |
| 人群面 | 谁焦虑、谁花钱、谁赚钱、谁影响决策？ |
| 情绪面 | 是焦虑、庆祝、社交、面子、方便，还是恐惧？ |
| 消费面 | 买商品、买服务、买信息、买陪伴，还是买效率？ |
| 渠道面 | 小红书、B站、微信、线下、社群，哪个更容易验证？ |
| 本地面 | 北京有哪些真实场景能靠近反馈？ |
| 政策面 | 哪些被鼓励，哪些不能碰？ |
| 工具面 | GitHub/开源/AI 工具能不能降低交付成本？ |
| 产品面 | 内容、服务、报告、工具、自动化、平台，哪种最轻？ |
| 组合面 | 它属于小现金流、中型服务，还是长期大实验？ |

## 4. 输出

每次扩展必须输出：

```text
种子信号：
十个机会面：
素材清单：
用户问题：
商业机会簇：
小实验：
中实验：
大实验：
第一现金流入口：
风险边界：
下一步动作：
```

## 5. 筛选规则

优先级不是看想法多酷，而是看：

```text
谁现在愿意付钱？
AI 能不能让交付更便宜？
我们能不能 7 天内验证？
失败后能不能学到东西？
有没有政策/平台风险？
```

## 6. 高考例子

```text
1：高考
10：祈福、陪考、考试服务、考后释放、志愿填报、录取、升学宴、入学装备、专业趋势、教育机构效率
100：家长问题、机构报价、小红书笔记、官方时间线、专业清单、商家活动、平台争议、工具模板...
3：志愿填报资料助手 / 高考后本地营销包 / 专业趋势内容产品
1：先做志愿填报内容素材包或本地商家营销包
```

## 7. 约束

- 发散后必须收敛。
- 列表必须进入实验，不停在脑暴。
- 不把高风险领域包装成确定性承诺。
- 不为了大而大，现金流实验优先提供学习速度。
