# 政策法规监测方法

> 日期：2026-06-07  
> 状态：生效草案  
> 适用范围：AI机会雷达 / 自运行 AI 商业闭环系统  
> 注意：本文件不是法律意见，只用于商业机会筛选和风险预警。

## 1. 为什么政策法规是核心输入

在中国市场，AI 商业机会不能只从产品发布、开源项目和海外新闻里找。

政策法规同时决定：

- 什么能做
- 什么不能做
- 哪些领域会被鼓励
- 哪些领域会有补贴、试点、场景开放
- 哪些方向有合规成本
- 哪些市场会因为监管变化出现新需求

所以政策法规不是“最后检查风险”的环节，而是商机发现的源头之一。

## 2. 监测目标

政策法规监测要回答 5 个问题：

```text
1. 新政策打开了哪些应用场景？
2. 新规则制造了哪些合规需求？
3. 哪些行业被明确鼓励做“人工智能+”？
4. 哪些行为有平台/监管风险？
5. 北京本地是否有可利用的试点、场景、补贴或线下资源？
```

## 3. 政策信号类型

| 信号类型 | 含义 | 商业意义 |
|---|---|---|
| 鼓励型政策 | 鼓励 AI 在某行业应用 | 找蓝海场景、示范项目、服务机会 |
| 监管型政策 | 提出限制、备案、标识、安全要求 | 找合规工具、审核服务、企业培训 |
| 场景开放 | 政府/行业开放试点场景 | 找早期客户和验证场 |
| 资金支持 | 补贴、基金、采购、示范项目 | 找付费来源和合作路径 |
| 标准规范 | 标准、标识、评测、认证 | 找工具化/咨询化机会 |
| 地方产业政策 | 北京/区级重点方向 | 找本地资源和线下验证机会 |

## 4. 常规监测频率

建议频率：

- 国家政策：每周检查
- 北京市政策：每周检查
- 区级政策：每两周检查
- 平台规则：每周检查
- 重大政策：实时记录

## 5. 每条政策如何处理

每条政策进入系统后，必须形成一条 `policy-signal`：

```text
政策名称：
发布机构：
发布日期：
适用范围：
政策类型：
鼓励方向：
限制方向：
可能产生的需求：
可能受益人群：
可能付费方：
合规风险：
蓝海评分：
下一步验证动作：
来源链接：
```

## 6. 风险分级

| 风险等级 | 判断标准 | 动作 |
|---|---|---|
| 低 | 内容、效率、内部工具类，风险较小 | 可进入普通商机池 |
| 中 | 涉及用户数据、生成内容、平台发布、企业流程 | 需要合规备注和人工审核 |
| 高 | 涉及金融、医疗、教育评价、未成年人、公共舆论、个人信息 | 只做调研，不直接商业化 |
| 禁止 | 明显违法违规或误导用户 | 不进入商机池 |

## 7. 输出物

政策法规监测要产生：

- `policy-signals.md`
- `policy-risk-notes.md`
- `policy-opportunity-candidates.md`
- `blue-ocean-policy-map.md`

## 8. 与商业蓝海的关系

政策法规监测不只是排雷。

它还用于发现蓝海：

```text
政策鼓励 + 用户痛点 + 供给不足 + 小团队可验证
= 高价值蓝海候选
```
